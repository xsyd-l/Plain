# Bug 修复日志

## BUG-1 精灵图错位：刚进游戏时精灵卡在玩家左侧

- **日期**：2026-09-20
- **版本**：初版动画系统（提交 `9b19ccc`）
- **现象**：进入游戏时，精灵图整体出现在玩家左侧约 96px 处。
- **根因**：
  - `Animation` 构造函数只设置了单帧 `textureRect`（32×32），没有设置 `origin`；
  - `Actor` 构造函数把 `origin` 设成了整张纹理图（256×32）的中心 `{128, 32}`；
  - `origin` 落在 32px 宽的单帧右边界之外 96px → 精灵被整体顶到玩家左侧。
- **修复**：在 `Animation` 构造函数中补上 `sprite_.setOrigin(foothold_)`，使 origin 相对单帧为 `{16, 32}`。
- **教训**：切分精灵帧后，`origin` 必须相对"当前帧的矩形"设置，而不是整张纹理。

## BUG-2 动画卡死 / 无法切换状态（间歇性、与启动环境相关）

- **日期**：2026-09-20
- **版本**：初版与现版本均存在
- **现象**：动画卡在第一帧、状态无法切换；且**时有时无**——同一可执行文件，有时正常有时卡死。攻击偶发不生效、伤害数值随机。
- **根因**：`Character` 的以下成员从未初始化（构造函数体为空）：

  ```cpp
  int health_;               // 堆上残留垃圾值
  int damage_;               // 垃圾值
  sf::Vector2f damagerange_; // 垃圾值
  float attackCoolDown_;     // 垃圾值
  ```

  - 卡死链路：垃圾 `health_ <= 0` → `getAnimationState()` 恒返回 `DEAD` → 未注册 DEAD 动画 → `toScreen()` 精确匹配与兜底全部失败 → 动画永远无法切换。
  - 间歇性来源：`make_unique` 分配的堆内存内容取决于启动时的分配器状态、ASLR 与历史写入数据，每次运行不同 → 运行时 bug，与编译无关。
  - 附带隐患：垃圾 `attackCoolDown_` 为巨大正数时攻击长时间被冷却拦截；垃圾 `damage_`/`damagerange_` 使伤害判定随机。
- **修复**：`include/entities/Character.hpp` 为成员添加默认初始化：

  ```cpp
  int health_ = 100;
  int damage_ = 10;
  sf::Vector2f damagerange_ = {50.f, 0.8f};  // {攻击距离, 角度上限(弧度≈46°)}
  float attackCoolDown_ = 0.f;
  ```

- **教训**：C++ 内置类型成员不会自动初始化；"时有时无、与环境有关"的运行时现象首先要排查未初始化内存。

## BUG-3 终端中文输出乱码

- **日期**：2026-09-20
- **现象**：`std::cout << "动画切换\n"` 在终端显示为 `鍔ㄧ敾鍒囨崲`。
- **根因**：源文件为 UTF-8，MinGW `std::cout` 直接输出 UTF-8 字节；Windows 控制台默认代码页 936 (GBK) 按 GBK 规则解码 → 每 2 个 UTF-8 字节拼成 1 个 GBK 汉字。
- **修复**：`src/Plain.cpp` 的 `main()` 开头调用 `SetConsoleOutputCP(CP_UTF8)`（`<windows.h>`，`_WIN32` 条件编译）。
- **教训**：Windows 下中文调试输出需保证"程序输出编码"与"控制台代码页"一致（UTF-8 ↔ 65001 或 GBK ↔ 936）。

## BUG-4 兜底动画每帧被重启，卡在第一帧

- **日期**：2026-09-20
- **现象**：当方向没有精确匹配的动画时（如对角移动），动画卡在第一帧不推进。
- **根因**：旧 `toScreen()` 每次进入切换分支都会对 fallback 动画重新调用 `start()`，帧索引被反复重置为第 0 帧。
- **修复**（与"补齐 8 方向动画判断"一并完成，见 `src/entities/Actor.cpp`）：
  - 方向收敛改为各分量独立取符号，保留对角方向，得到 8 方向单位向量 `{±1,0}`、`{0,±1}`、`{±1,±1}`；
  - `facing_` 静止朝向记忆同步改为 8 方向；
  - 匹配优先级：精确 8 方向 → 对角退化水平 → 对角退化垂直 → 同状态任意；
  - 加入 `chosen != current_animation_` 守卫：仅真正切换到另一个动画时才 `start()`，同一动画不再每帧重启。
- **备注**：`texture` 目录目前仅有 4 方向 × 2 状态纹理，对角移动自动退化播放水平动画；后续新增对角纹理时，用对角方向注册 `addAnimation` 即可，无需再改匹配逻辑。
